# ProductRelay 重命名、作品展示与公开发布设计

**日期：** 2026-08-18  
**状态：** 已确认
**涉及仓库：**

- 产品：`/Users/zevvv/vibe_coding/Hermes/pm-hermes`
- 个人展示站：`/Users/zevvv/vibe_coding/my job/zwj_resume_repo`

## 1. 目标

将当前接近成品的本地 AI 产品工作台统一重命名为 **ProductRelay**，以真实产品截图作为个人展示网页“项目作品”区的第一项，并将经过安全清理和完整验证的产品源码发布到公开 GitHub 仓库：

`https://github.com/marjorychase6-star/product-relay`

ProductRelay 的定位为：

> Your AI partner from insight to delivery.

面向独立产品经理，把资料、需求、PRD、原型和交付串联为可追踪、可审计、可由 AI 协助推进的完整工作流。

## 2. 已确认决策

- 公开 GitHub 仓库，而非私有或精简展示仓库。
- 产品品牌统一使用纯英文名 `ProductRelay`。
- 名称直接体现 Product 定位，同时保留 AI 搭档语义。
- ProductRelay 在个人网页的项目作品区置顶。
- 使用本地运行产品的真实截图，不使用概念图或生成式视觉。
- 先完成本地修改、验证与预览；最后才创建 GitHub 仓库并推送。
- ProductRelay 自有代码继续采用现有 MIT 许可；补齐根目录许可证文件。
- Hermes 继续作为明确标注来源和许可证的第三方运行时快照，不伪装为 ProductRelay 原创代码。

## 3. 范围边界

### 3.1 包含

- 产品可见品牌、页面标题、说明文案、README、包元数据和 CLI 名称更新。
- GitHub 仓库名、描述、README 首屏、安装和启动命令更新。
- 公开发布前的敏感信息、生成文件和本地数据审计。
- 一张经过裁切和压缩的真实主截图。
- 个人网页置顶重点项目卡片及其响应式样式。
- 产品仓库和个人网页仓库各自的测试、提交和推送。

### 3.2 不包含

- 不重命名内部 Python 包 `pm`；它是实现细节，重命名会制造无用户价值的导入迁移风险。
- 不修改 `third_party/hermes_agent` 内的上游品牌、历史、许可证或源码命名。
- 不在本轮新增 ProductRelay 独立营销站、在线 SaaS、云端后端或可操作网页演示。
- 不重构个人展示网站的其他项目卡片或整体视觉体系。
- 不上传本地数据库、附件、密钥、缓存、虚拟环境或构建目录。

## 4. 产品品牌迁移

### 4.1 面向用户的名称

所有 ProductRelay 自有界面中的 `pm-hermes`、`PM Hermes` 和同义旧品牌替换为 `ProductRelay`，包括：

- 应用导航和页面标题；
- 首次使用引导与示例项目文案；
- README、用户指南、架构说明和当前维护的验收文档；
- Python 分发名称与项目元数据；
- 桌面启动入口和命令帮助文本。

历史设计日志和明确描述迁移来源的内容可以保留旧名称，但必须避免让当前用户误认为产品仍叫 pm-hermes。

### 4.2 命令与内部接口

- 新的公开 CLI 命令为 `product-relay`。
- 当前产品尚未作为稳定公共版本发布，因此不保留旧 `pm-hermes` 命令别名。
- Python 导入包继续为 `pm`。
- 数据库 schema、命令协议版本和已有本地数据格式不因品牌迁移而改变。
- `third_party/hermes_agent` 路径保持不变，确保上游同步和许可证测试继续有效。

### 4.3 许可证与归属

- 根目录新增标准 MIT `LICENSE`，版权归属使用仓库所有者身份，不修改 Hermes 自身许可证。
- README 明确说明 ProductRelay 使用仓库内固定版本的 Hermes agent harness 作为运行时组件。
- 保留 `third_party/hermes_agent/LICENSE` 与 `UPSTREAM.md`，并验证来源提交信息可追溯。

## 5. 主截图设计

### 5.1 截图场景

使用内置完整示例项目，展示：

- 左侧产品生命周期导航；
- 中央事实型产品全局视图或结构化产物；
- 右侧 ProductRelay AI 助手；
- 手动确认/自动执行切换入口；

截图中不得出现真实 API Key、真实个人项目内容、本地绝对路径、调试终端或系统通知。

### 5.2 图片规格

- 桌面宽屏构图，目标比例约为 16:10。
- 优先保存为压缩后的 WebP；若现有网页兼容流程更适合 PNG，则使用优化 PNG。
- 文件放入 `static/images/projects/`，使用稳定名称 `productrelay-workspace.webp` 或对应 `.png`。
- 保证常见 Retina 屏幕清晰，同时控制网页资源体积。
- 图片 `alt` 文本描述实际界面和 AI 助手，不堆砌关键词。

## 7. GitHub 公开发布

### 7.1 发布前安全门

在创建远程仓库前必须完成：

- 扫描 Git 历史和当前工作树中的 API Key、令牌、密码、私钥及已知测试 canary；
- 确认 SQLite 数据库、附件目录、备份、导出包、日志、缓存和虚拟环境均未被跟踪；
- 检查 README、测试夹具和截图不存在个人敏感内容；
- 确认 `.gitignore` 覆盖 `.DS_Store`、本地数据根、构建产物和 IDE 文件；
- 检查 Git 中不存在超出 GitHub 限制的大文件或无必要二进制产物；
- 验证 Hermes 许可证和来源文件随仓库一起发布。

任一安全门失败时停止创建或推送远程仓库，先修复并重新验证。

### 7.2 仓库呈现

- 仓库名：`product-relay`
- 可见名称：`ProductRelay`
- 描述：`A local-first AI product execution partner for independent product managers.`
- 建议 topics：`product-management`、`ai-agent`、`local-first`、`prd`、`productivity`
- 默认分支：`main`
- README 首屏包含定位、主截图、核心工作流、运行要求、安装方式、安全模型、Hermes 归属和当前限制。

### 7.3 推送顺序

1. 产品仓库完成本地品牌迁移、安全审计和测试。
2. 创建公开 GitHub 仓库并推送 ProductRelay。
3. 确认公开仓库 URL 可访问。
4. 将最终 URL 写入个人网页卡片。
5. 本地预览个人网页并验证链接。
6. 经用户确认后推送个人网页仓库。

不得覆盖远程历史、强制推送或自动删除现有远程内容。

- 品牌替换必须按文件类别审查，禁止对 `third_party/hermes_agent` 做全仓机械替换。

- 产品与个人网页使用独立提交；任一仓库失败不应把另一仓库置于半发布状态。
